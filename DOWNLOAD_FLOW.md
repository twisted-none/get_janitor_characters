# Download Flow

## Automatic Public Janny Fallback (Docker, 2026-10-23)

Текущая цепочка: DataCat → JannyAI public-page export → Janitor proxy → подключённый LLM. Полная карточка DataCat завершает цепочку сразу. Ошибка DataCat или отсутствие определения переводит запрос на JannyAI. Ошибка браузера сохраняет последующий proxy fallback и прежний выбор частичной карточки.

В Docker этап JannyAI использует Camoufox 0.5.8 в отдельном Python-окружении с Playwright 1.62.0; основной Playwright 1.63.0 и Chromium не меняются. Firefox 156.0.1-beta.36 и закреплённая модель fingerprint устанавливаются и проверяются по SHA256 при сборке. При отсутствии модели этап завершается с browser_missing; установка при запуске не выполняется. Текущий бинарный пакет предназначен для Linux x86_64.

Браузер работает в Xvfb с новым временным HOME и профилем. Проверка Cloudflare ожидается ограниченное время; флажок текущего шаблона нажимается через системный X11 XTEST. Cookies аккаунтов, BOT_TOKEN и DATABASE_URL не передаются. На странице читается JSON props компонента Astro CharacterButtons; JavaScript из метаданных не исполняется. Проверяются UUID, origin, обязательные поля и признаки приватности. Из публичных полей создаётся PNG Character Card V2 с определением, сценарием, первым сообщением, примерами, заметками автора и тегами. Bookmark — избранное, в скачивании не участвует. Книги обрабатываются прежним модулем lorebooks только при фактическом наличии данных.

Native TLS браузера проходит через локальный CONNECT-туннель, который разрешает только jannyai.com, api.jannyai.com, image.jannyai.com и challenges.cloudflare.com на порту 443. Каждое подключение использует проверенный публичный IP без повторного DNS при соединении; приватные адреса запрещены. Ограничения: 200 подключений/запросов, 32 одновременных туннеля, 64 MB суммарного трафика, конечные deadlines. WebSockets, service workers и WebRTC отключены. Аватар загружает прежний pinned HTTPS-клиент. Внешний worker сохраняет тайм-аут и завершение всей группы процессов, включая отмену.

Живой прогон в одноразовом read-only Docker: DataCat вернул CREATOR_REDIRECT_REQUIRED / 403; затем JannyAI автоматически скачал a6c77849-5700-4e4d-b161-29272b875d12 за 20,84 секунды на всю цепочку. Получен PNG 1106×1102, 1 178 519 байт. Независимо подтверждено точное совпадение определения (10 487 символов), сценария (828), первого сообщения (4 162), примеров, заметок, автора и 7 тегов с публичными данными. Книг в ответе этой карточки нет. Артефакты: .cache/janny-integrated-20261023/.

Проверены 159 unittest-тестов без сети, запуск Camoufox и системный клик на локальном HTML в read-only контейнере, отмена native worker с очисткой дочерних процессов. Это успешная текущая проверка; изменения Cloudflare, DOM/формата Astro, доступности карточки или IP могут потребовать обновления адаптера. Старые наблюдения ниже описывают предыдущие реализации. Запущенный janitor_test_bot и сервер этой работой не обновляются.

## Janny PNG Recheck 2026-10-23

Исправлен подтверждённый дефект: JannyAI сохраняет chara в tEXt после IDAT, поэтому Image.open().info ещё не содержит определения. Общий PNG-reader теперь проверяет разрешение, вызывает image.load(), затем читает ограниченный chara. Проверка proxy-маркера использует тот же reader без ужесточения прежних требований к наличию остальных полей. Добавлены регрессионные тесты хвостового tEXt, нормализации, proxy-маркера и усечённых данных. Все 146 тестов прошли в Docker на Python 3.14.8.

Получен настоящий PNG кнопкой Download в обычной браузерной сессии после ручной проверки пользователя. Его поля совпали с присланным пользователем файлом; исходный файл не изменён. Проверены три варианта экспорта без изменения пикселей и определения; PNG отправлен пользователю через @twistedprojects_testbot с явной подписью о браузерном способе получения.

Это не исправление автоматического доступа к JannyAI: обычный публичный POST API из Windows и Docker вернул 403 / text/html. Встроенный браузер сначала также показал Cloudflare; после ручной проверки кнопка Download сработала без входа в аккаунт. Browser-session не копировалась в worker, cookies и токены не извлекались. Защита SSRF и подмена запросов браузера через pinned HTTPS не отключались. Полная автоматическая загрузка через текущий контейнер для этой карточки остаётся неподтверждённой и при последней проверке заблокированной.

Источники: [Pillow PNG implementation](https://pillow.readthedocs.io/en/stable/_modules/PIL/PngImagePlugin.html), [обычная интеграция JannyAI в SillyTavern](https://github.com/SillyTavern/SillyTavern/blob/release/src/endpoints/content-manager.js#L548).

## Detailed Diagnostics And Lorebooks

Итоговая локальная проверка: 142 теста прошли в Docker на Python 3.14.8; pip check не выявил конфликтов. Chromium sandbox и синтетические сценарии Janny API/page, proxy и приватности проверены. На отдельной PostgreSQL проверено сохранение настройки между инициализациями и отсутствие её влияния на другого пользователя. Образ janitor-bot:lorebook-check запущен в janitor_test_bot с проверкой @twistedprojects_testbot; рабочий бот и сервер не обновлялись. AST-граф, отчёт и HTML-карта обновлены локально без семантического анализа.

Команда /settings открывает выбор: отдельные JSON-файлы, лорбуки внутри PNG или оба варианта. По умолчанию используется separate. Значение сохраняется в PostgreSQL user_preferences по Telegram user_id; callback не принимает чужой ID. Настройки доступны в личном чате. Таблица создаётся автоматически без изменения существующих данных.

Извлекаются все лорбуки и записи, которые источник фактически предоставил: встроенный character_book, scripts/lorebooks в ответе карточки и scripts из исходных метаданных PNG. JSON5 применяется только для разбора литерала loreEntries; JavaScript не выполняется. Новые догадочные API для обхода закрытых лорбуков не используются. Если есть ссылка/описание без содержимого или неподдерживаемый исходник, лорбук учитывается как недоступный; отправляется предупреждение. Наличие всех лорбуков на исходном сайте без отдачи их содержимого не гарантируется.

Для PNG записи всех книг объединяются с последовательными ID; настройки исходных книг сохраняются в extensions.source_books, дополнительные параметры записей в extensions.source_entry_options. Для отдельных файлов используется JSON world-info с entries-объектом. Различающиеся глобальные настройки нескольких книг не могут одновременно управлять одним character_book; их оригинальные значения сохраняются как метаданные. Экспорт создаётся отдельно на отправку, исходная карточка не изменяется; временные файлы очищаются и при ошибке отправки. Закрытые исходники не экспортируются.

В журнале download_event: общий job, источник, операция, метод, безопасный шаблон адреса, HTTP-статус, тип и размер ответа, время, лимит ожидания, наличие определения и число книг. События из worker передаются ограниченным JSONL и выводятся после завершения процесса, в том числе при его ошибке. На процесс сохраняется не более примерно 128 KiB событий, ретрансляция ограничена 512 событиями. Произвольные сообщения исключений, тела ответов, cookies, заголовки авторизации и параметры URL не передаются.

Проверка 2026-10-22: у a6c77849-5700-4e4d-b161-29272b875d12 identify вернул 200, lookup с sourceKind=janitor вернул 403 / CREATOR_REDIRECT_REQUIRED. Это ограничение политики автора, а не ошибочно добавленный recent. Страница /characters/recent/{UUID} и вариант /characters/recent/janitor/{UUID} вернули 403; /characters/{UUID} вернула HTML 200, но HTML-оболочка не отменяет отказ API. У 825c13ae-a777-4c7a-8566-0e262420ba5e тот же API вернул 200, PNG получен размером 478203 байта; в этом ответе не было лорбуков. Экспорт нескольких книг проверяется синтетическими примерами, не заявляется как проверка всех живых карточек.

Для ссылок JanitorAI и JannyAI применяется один порядок:

Языковой префикс и декоративное название после `_` не входят в идентификатор скачивания. Название может содержать Unicode и корректные `%XX`-последовательности; в источники передаётся только ID перед `_`. Проверка домена и ограничение длины самого ID сохраняются.

1. DataCat: читается существующая карточка. Если определение есть, PNG отправляется без поясняющей подписи.
2. JannyAI: используется, когда DataCat недоступен, карточки нет или она не содержит определения.
3. JanitorAI: проверяется открытое определение и существующий способ через разрешённый автором proxy.
4. LLM не подключён. Если ни один источник не вернул полное определение, отправляется доступная неполная карточка; при отсутствии карточки сообщается об ошибке.

После первого полного результата дальнейшие источники не вызываются. Публичное описание страницы само по себе не считается определением. Стандартное поле description готовой Tavern-карточки может содержать определение; для DataCat оно сравнивается с публичным описанием источника.

Если полного результата нет, возвращается первая доступная неполная карточка с предупреждением. Если нет даже такой карточки, пользователь получает ошибку. Ветки LLM в тестах используют имитацию провайдера, а не живую модель. Текст модели должен маркироваться как восстановленный, без утверждения о точном оригинале.

Источник и состояние определения сохраняются в extensions.download_bot внутри PNG. Для proxy также остаётся отметка janitor_proxy_prompt, когда исходное определение получено этим способом.

## Status Messages

Для каждой карточки бот сначала показывает сообщение очереди с 0%, даже если слот свободен. После начала работы сообщение очереди удаляется и появляется активный статус. Он показывает полосу из пяти индикаторов, примерный процент и текущий источник: DataCat, JannyAI, proxy или недоступный LLM-этап. Процент монотонно растёт по этапам и времени, но не означает долю полученных байтов; до отправки он ограничен 95%. Перед отправкой PNG статус показывает 100%, после успешной отправки удаляется. Активный статус обновляется каждые пять секунд, а быстрые переходы между источниками показываются сразу с ограничением частоты правок Telegram. Ошибка изменения или удаления статуса не отменяет успешное скачивание.

## Sessions And Files

Учётные данные JannyAI берутся только из JANNYAI_EMAIL и JANNYAI_PASSWORD. JANITORAI_EMAIL, JANITORAI_PASSWORD и сохранённая сессия JanitorAI не передаются JannyAI. DataCat получает только собственный анонимный идентификатор сессии; облачное извлечение не запускается.

Временные PNG получают уникальные имена. Каждый источник запускается в отдельном процессе с собственным временным каталогом; токены Telegram и пароль БД в его окружение не передаются. На источник отводится до 300 секунд, на всю цепочку действует DOWNLOAD_TIMEOUT_SECONDS. При отмене или таймауте дерево процессов принудительно завершается до освобождения слота. Неполные промежуточные карточки удаляются после выбора результата; итоговая карточка удаляется после отправки или ошибки Telegram.

В общей очереди допускается до 1000 ожидающих задач. Если ждут разные пользователи, одному выделяется не больше пяти запусков подряд, затем очередь переходит к следующему. Одиночный пользователь продолжает без ограничения общего количества скачиваний. При нескольких рабочих слотах порядок определяется началом задач, а не временем их завершения.

Публичная карточка со скрытым определением не считается приватной. Через общую авторизованную сессию Janitor разрешены только карточки с явно подтверждённой публичностью. Приватная карточка или неизвестная видимость отклоняются до создания proxy-чата.

Сетевые запросы ограничены HTTPS и разрешёнными доменами. DNS-адреса проверяются и фиксируются при подключении; внутренние адреса и опасные перенаправления блокируются. Ограничены число запросов страницы, объём ответов и размер изображения. PNG содержит только разрешённые поля карточки, без произвольного исходного JSON с данными аккаунта.

## Validation

Ошибки источников передаются из worker в виде разрешённых полей code, error_type, http_status и exit_code. Сырые исключения, traceback, HTTP-body, cookies и токены через этот канал не передаются. Журнал download_source_failed показывает источник, безопасную причину и длительность; уведомление администратору содержит коды источников и известные HTTP-статусы. При полном отказе пользователь получает общую ошибку без упоминания LLM. Наличие неполной карточки по-прежнему приводит к отправке PNG с предупреждением об отсутствии определения.

Локальные проверки: python -m unittest discover -s tests -v в окружении из requirements.lock. Тесты проверяют маршрутизацию, короткое замыкание цепочки, PNG-метаданные, ошибки и статусы Telegram, очередь, отмену, SSRF и изоляцию учётных данных. Живое получение через JanitorAI не проверено: браузерный доступ ранее заблокирован средой. Подключённого LLM-провайдера по-прежнему нет.

Браузерный слой использует официальный Chromium, устанавливаемый вместе с закреплённым Playwright при сборке. Sandbox обязателен. tools/browser_smoke.py проверяет настоящий браузер и цепочки Janny API / fallback к странице / Janitor proxy на ответах из памяти, без внешней сети. Это не проверка совместимости с живой защитой сайтов. Инструкции локальной подготовки, проверки сессии, backup и отката: PREDEPLOY.md.

Локальный граф строится без семантической обработки: graphify extract . --code-only, затем graphify cluster-only . --no-label. Исключения секретов и зависимостей находятся в .graphifyignore. Файлы graphify-out/ не включаются в Git и Docker-контекст.
