# Shared Alert Buttons

Один общий алерт-бот получает нажатия только через уже существующий polling в Ficbook. Его кнопки сохраняют префикс `alert:retry:`, кнопки карточек используют `janny:retry:`. Второй polling общего токена не запускается.

Ficbook передаёт нажатие в `http://janitor_characters_bot:8001/retry` внутри Docker-сети `bot-alerts`. Тело ограничено 2048 байтами и подписано HMAC-SHA256 с существующим общим токеном алерт-бота; токен не передаётся в запросе и не пишется в логи. Подпись действует 60 секунд. Внешние адреса и перенаправления запрещены. Дополнительный секрет не требуется. Порт 8001 не публикуется на хосте.

Бот карточек проверяет администратора, чат, бота-отправителя алерта и его message_id по сохранённому запросу. Случайный идентификатор кнопки не содержит пользовательских данных. Адрес получателя и исходная ссылка берутся из PostgreSQL, а не из нажатия. Вызов скачивания идёт через обычную очередь, с настройкой лорбуков, сохранённой при создании алерта. Файлы отправляет основной бот исходному пользователю.

Таблица `card_alert_retries` создаётся при запуске идемпотентно. Запросы действуют 30 дней и переживают перезапуск; устаревшие удаляются при создании новых алертов. PostgreSQL advisory lock защищает один запрос от одновременной обработки. Процесс держит максимум две ручные повторные отправки, включая ожидание очереди.

Отправленные PNG и JSON лорбуков фиксируются отдельно. Повтор пропускает PNG и совпадающие по содержимому уже отправленные лорбуки. После полной доставки алерт удаляется. Если удалить его не удалось, следующее нажатие повторит только удаление. При неудаче кнопка возвращается в исходное состояние, а алерт остаётся. Ошибка ручного повтора не создаёт новый алерт и не назначает ещё один автоматический цикл ожидания.

Старые текстовые алерты без сохранённой записи не изменяются. Кнопка добавляется к новым алертам только после привязки сообщения к записи БД; сбой БД не мешает отправить обычное уведомление об ошибке. Подтверждение доставки записывается после ответа Telegram: авария между ответом Telegram и фиксацией в БД теоретически допускает повторную отправку этого файла.

## Deployment

Нужно обновить оба проекта. В Ficbook изменены только маршрутизация алертов и Compose; в проекте карточек — обработка повторной доставки, её хранение и Compose/Dockerfile. Настройки токенов и `.env` сохраняются. На рабочем сервере в этой задаче изменения не применялись.

Один раз создать общую внешнюю Docker-сеть, если её ещё нет (команды Linux на сервере):

```sh
docker network inspect bot-alerts >/dev/null 2>&1 || docker network create bot-alerts
```

Затем пересобрать и пересоздать оба сервиса из их каталогов:

```sh
cd /srv/projects/get_janitor_characters_bot
docker compose up -d --build
cd /srv/projects/ficbook_downloader_bot
docker compose up -d --build
```

Сеть обязательна для обоих новых Compose-файлов. Поэтому создать её нужно до пересоздания сервисов. Не включать второй polling общего алерт-бота в проекте карточек. Если общий токен не настроен и алерты отправляет основной бот карточек, его собственный обработчик принимает эти кнопки напрямую.

## Verification

Проверки выполняются локально в Docker с фальшивыми Telegram-токенами и отдельной временной PostgreSQL. Проверяются подпись и срок запроса, исходный получатель, ограничение доступа, блокировка двух нажатий, сохранение подтверждений по файлам, частичная доставка и повторное удаление алерта. Сквозная проверка использует реальный код relay из Ficbook, HTTP-приёмник карточек, PostgreSQL и обработчик общей очереди; Telegram API и загрузка исходного файла подменяются. Реальным пользователям тестовые сообщения не отправляются.

Итоговая проверка 2026-10-27: 201 тест проекта карточек и 546 тестов Ficbook прошли без пропусков с временной PostgreSQL. Отдельная сквозная проверка подтвердила, что повторное событие не отправляет документ пользователю снова. Проверены оба Compose-файла без чтения env-файлов. Графы исходного кода обоих проектов обновлены.
