# Local Predeploy

Подготовка выполнена только локально. Ничего не опубликовано, рабочий бот и его база не переключались. .env и реальные cookies не читались. Локальные тесты используют фиктивные реквизиты.

Итог: 99 тестов прошли; pip check без конфликтов; pip-audit по 25 пакетам без известных уязвимостей; компиляция Python с предупреждениями как ошибками прошла. Браузерные сценарии и полный backup/restore на временной PostgreSQL прошли. Тестовые контейнер БД и сеть удалены. Синтаксис Compose проверяется отдельно на .env.example без загрузки настоящего env_file.

## Runtime

Python 3.14.8, Playwright 1.63.0, поставляемый им Chromium 153.0.8010.12. CloakBrowser удалён из зависимостей. Chromium установлен в read-only слой образа /opt/ms-playwright, версия соответствует закреплённому Playwright. После обновления Playwright пересобирайте образ. Стандартный Windows Python не заменялся.

Браузер работает с sandbox, от пользователя UID 10001, без capabilities, с no-new-privileges и seccomp-профилем. Реальный браузер проверен без сети: отрисовка, статус sandbox, download API Janny, fallback к странице, proxy и отказ приватной карточке. Ответы сервисов в этих проверках синтетические; прохождение CAPTCHA, действующая авторизация и совместимость с живыми сайтами не доказаны.

Политика приватности не изменилась: скрытое определение публичной карточки допускается, приватная карточка через общую сессию запрещена. Порядок DataCat -> JannyAI -> Janitor proxy сохранён. LLM не подключён и не выдаётся за работающий источник.

## Local Checks

Образ для проверки: janitor-bot:local-check. Собрать заново:

```powershell
docker build -t janitor-bot:local-check .
docker run --rm --network none --mount "type=bind,source=$($PWD.Path)\tests,target=/app/tests,readonly" --workdir /tmp -e PYTHONPATH=/app -e MY_COOKIES= -e PYTHONDONTWRITEBYTECODE=1 janitor-bot:local-check python -m unittest discover -s /app/tests -q
docker run --rm --init --network none --read-only --cap-drop ALL --security-opt no-new-privileges:true --security-opt seccomp=./docker/seccomp-browser.json --shm-size 256m --memory 1536m --pids-limit 256 --tmpfs /tmp:rw,nosuid,size=256m,mode=1777 janitor-bot:local-check python tools/browser_smoke.py
```

В production-образе есть preflight, но нет PostgreSQL CLI. Отдельный docker/Dockerfile.local-check добавляет CLI только для локальных проверок. Он использует PostgreSQL client 15; для реального backup необходим pg_dump той же основной версии, что сервер, либо совместимой более новой версии. Не считайте тест на PostgreSQL 15 подтверждением совместимости с вашей неизвестной версией сервера.

Docker HEALTHCHECK проверяет /health каждые 30 секунд после периода запуска. Это liveness-проверка HTTP, а не гарантия доступа к БД, Telegram или источникам.

## Settings And Session

.env.example содержит только заполнители. Реальные BOT_TOKEN и DATABASE_URL обязательны. Пары EMAIL/PASSWORD задаются полностью либо остаются пустыми. Транспортный CLOAKBROWSER_PROXY не поддерживается закреплённым HTTPS-клиентом; при его наличии preflight завершается ошибкой. Это не относится к Janitor proxy как способу получения определения.

Перед самостоятельным запуском выполните в выбранном окружении:

```powershell
python tools/preflight.py --browser
```

Команда сама .env не загружает и значения не печатает; переменные должны быть предоставлены окружением запуска. Для проверки именно Compose после самостоятельной сборки можно использовать `docker compose run --rm --no-deps bot python tools/preflight.py --browser`: это не запускает polling, но создаёт одноразовый контейнер и том кеша. Не выводите `docker compose config` или `docker inspect` с Environment в общедоступные журналы.

SESSION_FILE: ABSENT означает отсутствие сохранённой сессии; автоматический вход возможен только с корректной парой Janitor EMAIL/PASSWORD и при отсутствии блокировки сайта. PRESENT_NOT_VALIDATED подтверждает только наличие файла, а не действительность токена.

Сессия по умолчанию находится в /app/.cache/janitor_auth_state.json внутри тома janitor_cache. Существующая Windows-сессия автоматически не переносится. Для импорта используйте собственный доверенный файл Playwright storage_state, вручную поместите его в этот том и назначьте владельца 10001; файл не должен попадать в образ или Git. Перед переносом сохраните закрытую резервную копию тома. Альтернатива для локального ручного входа: установить зависимости и `python -m playwright install --no-shell chromium`, затем самостоятельно запустить janitor_login.py в разрешённом окружении. Агент этот вход не выполнял.

## Backup And Rollback

Перед вашим деплоем сохраните идентификатор и локальный тег текущего рабочего образа. Не удаляйте старый образ и не выполняйте `docker compose down -v`: это может удалить сессию. Зафиксируйте текущую конфигурацию закрытым способом, без вывода секретов в отчёт.

В текущем Docker нет контейнера janny_ai_bot, поэтому предыдущий рабочий образ по нему определить и пометить для отката не удалось. Старый тестовый janitor-bot:security не считается проверенным production-образом для отката.

Резервное копирование выполняется инструментом tools/db_backup.py в окружении с DATABASE_URL и установленными pg_dump/pg_restore:

```powershell
python tools/db_backup.py .cache/backups/before-deploy.dump
```

Существующий файл никогда не перезаписывается. Пароль не передаётся в аргументах процесса; дамп проверяется `pg_restore --list`, рядом создаётся SHA256. Дамп содержит конфиденциальные данные: храните его локально в закрытом месте, не включайте в Git/образ/граф. Настоящий backup рабочей БД в этой задаче не создавался. Создание и восстановление проверены на одноразовой локальной PostgreSQL с вымышленными пользователями и скачиваниями.

Перед использованием реального дампа проверьте SHA256 и восстановите его в отдельную пустую тестовую БД, затем проверьте таблицы и данные. Только проверка списка архива не доказывает восстановимость. Никогда не проверяйте восстановление поверх рабочей базы.

При неудачном обновлении сначала остановите новый polling, верните предыдущий образ и совместимую конфигурацию, запустите один экземпляр бота. В текущем обновлении разрушающих миграций БД нет; восстановление дампа поверх production не является обычным шагом отката и требует отдельного решения из-за потери более новых данных. Затем проверьте health, логи без секретов и пробное скачивание. Возвращать старую сессию нужно только если она была изменена и её резервная копия ещё действительна.

## Remaining Live Checks

Самостоятельно в разрешённом окружении проверьте авторизацию, доступность живых JannyAI/JanitorAI и карточки разных типов. При отказе WAF/CAPTCHA не отключайте sandbox и не обходите ограничения; остановите этот источник и используйте доступные разрешённые источники/экспорт владельца. Успешные локальные фикстуры не гарантируют успешную работу чужого API после его изменения.
