# Alert retry logs

События `alert_retry_clicked`, `alert_retry_started`, `alert_retry_file_sent`,
`alert_retry_succeeded` и `alert_retry_failed` записываются в стандартный лог.
`retry_id` связывает этапы одной попытки, `alert_id` указывает исходное сообщение.
Обработанные ошибки и частичная доставка тоже оставляют причину отказа,
классы исключений и позиции в стеке. Тела ответов, токены и cookies в эти
события не попадают; публичные ссылки записываются без query и fragment.

После обновления обоих ботов и нажатия кнопки просмотр:

```bash
docker logs --since 30m janitor_characters_bot 2>&1 | grep alert_retry_
```

Для одного алерта добавьте фильтр по `alert_id`, для одной попытки — по `retry_id`.
Если карточка уже доставлена, повторный клик повторяет только удаление алерта.
